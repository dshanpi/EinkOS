# 新板接入与每次发布检查表

使用 [规范正文](SPEC.md) 与 [字段约定](CONTRACT.md)。复制本表到项目任务记录，逐项填写
负责人、完成日期和证据位置。未执行项保持未勾选；“完成文档”不等于已经实现或实测。

## 新板首次接入

- [ ] 确定应用仓库、硬件/SDK 原仓库和开发分支、Release 所在应用仓库及维护者。（R01–R04）
- [ ] 从 [板卡模板](templates/board-profile.json) 建立 `boards/<board-id>/board-profile.json`。
      填写板型/修订、SoC/架构、存储/分区、显示/输入、可选网络、SDK、工具链、构建目标及恢复方式。（B01）
- [ ] 确认 LYNX 支持及安装入口；未支持先适配，不能将未经验证的其他刷机步骤冒充 LYNX 支持。（B03）
- [ ] 建立用户态与板级适配，硬件包配方固定应用来源；归档 SDK 覆盖层/补丁与额外输入。（R02、V01、C02）
- [ ] 提供主机测试、目标构建、系统打包、镜像内容检查及硬件测试入口；实现本规范所需门禁。
- [ ] 提供 README 全页面截图、架构和功能实现、构建安装、版本边界、开发 AGENTS/Skill 文档。（D01–D03）
- [ ] 用错误应用提交、错误板型/镜像、移动标签、缺失 SDK 输入或验证证据验证门禁确实拒绝继续。

## 每次发布的九个步骤

| 步骤 | 输入与操作 | 必须留下的交付 | 继续条件 |
| --- | --- | --- | --- |
| 1 定范围 | 确定发布版本、板卡矩阵、目标阶段及功能变化 | 发布任务、profile、变更说明 | 板型与存储/显示变体明确，仓库责任明确 |
| 2 定应用 A | 提交代码/版本、逻辑测试、UI 截图、独立源码构建 | 完整应用提交 A、源码来源、测试/截图记录 | 应用版本和源码标识一致，测试通过 |
| 3 定硬件 H 与 SDK | 配方固定 A 和归档哈希；提交驱动/设备树/配置；锁定 SDK 组件及补丁 | 完整硬件提交 H、SDK 清单、配置及额外输入 | 没有未记录的构建输入，配方实际引用 A |
| 4 构建与核对 | 用固定输入交叉编译、构建系统、打包，读取实际镜像内标识 | 原始 `.img`、构建记录、日志、镜像内容核验 | 构建产物对应 A/H/SDK/profile，不是旧镜像 |
| 5 实机验收 | 用该镜像完成 LYNX 烧录、启动/恢复及板卡能力测试 | 绑定镜像哈希的 validation、环境/测试者/日期/日志 | 实际记录 passed/failed/not_run，适用规则明确 |
| 6 组装发布包 | 创建固定标签，压缩镜像、生成源码包与逐板记录、锁及校验和 | 全部 [资产](SPEC.md)、应用标签、硬件标签 | 版本、源码包、标签、配方、板型、镜像哈希一致 |
| 7 上传草稿 | 通过离线门禁及远端标签/配方校验，上传到应用 Releases | Draft 与全部附件、版本表及安装/已知问题说明 | 资产完整；失败原因保留，写入重试先查远端状态 |
| 8 远端复核 | 下载实际附件重新校验、确认来源审核、检查验收状态 | 针对远端附件的门禁结果 | 预发布/正式版的对应门禁全部通过 |
| 9 公开与留档 | 改变 Release 可见性/阶段；同步版本索引和两个仓库链接 | 公众下载页、版本映射、验证证据及记录提交 | 附件与标签冻结，下一次更改走新版本 |

A/H 确定后即可创建固定标签；第 6 步是检查它们已经存在并指向实际构建输入，不要求拖到构建后才创建。
应用/硬件提交不能互相包含尚未生成的提交号；构建后的锁和文档单独留档，避免循环。

## 发布维护者最后检查

- [ ] 下载的是 GitHub 上实际准备公开的全部附件，已逐项核对 SHA256SUMS。
- [ ] 压缩包可解压，解压镜像哈希与锁及 validation 相同；板型、分区、存储容量正确。
- [ ] 应用标签解析到 A；硬件标签解析到 H；H 中配方固定 A；SDK/补丁/配置身份完整。
- [ ] profile、build-info、SDK 清单、源码和镜像均被锁或校验和覆盖。
- [ ] 完整系统对应源码及厂商说明可获取，审核记录绑定本镜像。
- [ ] 阶段符合门禁；多板逐板核验，没有用一块板的测试结果替代另一块。
- [ ] 安装链接统一指向 LYNX，说明解压、校验、备份、板卡模式、分区风险和恢复步骤。
- [ ] README 与 Release 说明中的支持范围、截图和已知问题与本次实际交付一致。

## 何时停在哪个阶段

没有完整镜像/配套资产：仍是开发任务，不宣称已经形成固件 Release。
资产完整且身份一致但缺来源/补丁或硬件验收：保持 Draft 并列明缺项。
构建、身份和来源审核通过且 LYNX 支持明确，硬件未测项充分披露：可以公开 Pre-release。
全部适用实机检查通过：可以发布 Stable。已知失败项不得通过改名为未测或不适用来绕过门禁。
