# 接入新板卡与屏幕

EinkOS 当前板卡为 **`100ask_t113s3-pro`**。后续 Linux 板卡复用桌面和应用逻辑，通过系统契约与平台适配接入；板卡型号、Linux 系统和屏幕规格共同组成一个发布目标。

本文是后续接入流程。当前已经存在的是 Tina / OpenWrt、240×360 单色 EPD 的用户态适配；多板规范本身不产生新的驱动、服务后端或可安装镜像。

## 1. 统一板卡名称，保留历史身份

| 使用场景 | 名称与处理方式 |
| --- | --- |
| 当前产品板卡名称 | `100ask_t113s3-pro`，本文及新用户指南采用此名称 |
| 历史文档称呼 | `100ASK T113-PRO`，用于理解已有资料；选择镜像仍须核对硬件修订、存储和屏幕 |
| 现有镜像文件标识 | `100ask-t113-pro-240x360`，保持既有文件名、哈希和版本锁不变 |
| 硬件仓库名称 | `100ASK_T113-PRO_TinaSDK5`，保持现有仓库地址和固定提交 |
| 后续新系统的机器标识 | 在真实 board profile 和系统契约中明确选定，记录与历史标识的映射及适用范围 |

名称说明不允许更新器自动替换 `-`、`_` 或模糊匹配板型。历史镜像也不能只改名便作为新的板卡包发布。

## 2. 为每个安装目标建立档案

按[新板接入检查表](../standards/linux-board-release/v1.0.0/ONBOARDING.md)建立板卡 profile，记录以下真实信息：

- 板型、硬件修订、SoC/架构、调用 ABI、libc、加载器和工具链/sysroot。
- NAND/eMMC/SD 等存储类型、容量、布局、可写应用区、用户数据区和恢复入口。
- 屏幕控制器、分辨率、方向、色深、波形/刷新能力、连接方式及输入设备。
- Linux/SDK 基线、init、网络/蓝牙/时间服务及应用依赖。
- LYNX 安装支持、应用 OTA 能力和系统 OTA 能力，三项分别记录。

先按[不同系统安装说明](SYSTEMS.md)确定集成方式。相同板卡运行 Tina 和 Debian 应分别建立运行环境目标；相同 CPU 不足以共享二进制。只有契约、后端、依赖及实测均证明兼容，多个板卡才可以共用某个应用包。

## 3. 实现平台适配

| 接入部分 | EinkOS 仓库中的工作 | 板级/系统仓库中的工作 |
| --- | --- | --- |
| 显示 | 用户态后端、缓冲格式转换、刷新策略及错误报告 | 内核驱动、设备树、控制器初始化、波形与引脚 |
| 输入 | 按键/触摸事件映射和页面交互 | 输入驱动与设备权限 |
| 网络/蓝牙 | 调用目标系统接口的后端及不可用降级 | 驱动、固件、系统服务及其稳定接口 |
| 进程管理 | 适配服务定义、依赖及健康检查 | init、权限、日志、启动与恢复条件 |
| 应用更新 | 目标应用包、兼容清单及发布验收 | 更新器、信任根、系统契约和应用/数据目录基础设施 |
| 系统更新 | 描述应用兼容性及迁移要求 | 系统 OTA 后端、启动链、分区/卷布局、镜像与救援 |

当前 `platforms/tina/` 是具体 Tina 用户态实现，不是所有 Linux 板卡的默认后端。复用它前须确认其厂商依赖和 EPD ioctl 在目标系统真实存在。

## 4. 改变屏幕尺寸时需要做什么

当前 UI 为固定 240×360，EPD ABI 的单帧为 10800 字节。新增 400×300、其他方向、灰阶或不同刷新控制器时，至少需要：

1. 定义新显示目标的分辨率、像素格式、行跨度、缓冲大小、旋转和刷新接口。
2. 调整布局、字体、分页和交互，处理长文字、弹窗及异常状态，不能只把旧帧拉伸。
3. 保留旧目标的接口行为；破坏性 EPD ABI 改动由系统发布及契约迁移承载。
4. 用生产渲染路径为各目标生成截图并检查裁切/缺字；实机验证全刷、局刷、残影、BUSY 超时和恢复。
5. 在应用目标矩阵中区分显示后端与系统契约，拒绝向旧 240×360 系统下发不兼容载荷。

当前 `make screenshots` 只覆盖既有目标。新增目标须扩展捕获工具和证据清单，不能将旧图库作为新屏幕的验收材料。

## 5. 分阶段交付

| 阶段 | 对外能说明什么 | 必需结果 |
| --- | --- | --- |
| 规划 | 接入目标与范围 | profile 草案、职责和缺项；不能作为安装支持列表 |
| 可构建 | 源码可针对目标编译 | 工具链、依赖、主机测试和目标产物 |
| 可安装使用 | 指定系统可启动桌面并使用声明功能 | 匹配镜像/应用、LYNX 路径、硬件验收、用户指南和截图 |
| 应用 OTA 可用 | 指定来源应用可更新到目标应用 | 签名/兼容检查、事务/断电恢复、健康回退和数据保护 |
| 系统 OTA 可用 | 指定来源系统可在线升级到目标系统 | 系统升级后端、启动确认/回退、数据迁移和最终救援验收 |

应用 OTA 和系统 OTA 分别放行。一块板可以先交付 LYNX 安装和应用 OTA，再独立完成系统 OTA；不能因为后一项未实现，就要求每次兼容桌面更新重刷系统。

发布时列出每个目标的系统基线、应用版本、支持功能、安装方式和两种 OTA 状态。更新器按照明确兼容集合选择目标，不使用“支持 Linux”或 CPU 型号概括所有板卡。
