# 在不同 Linux 系统上安装与使用

本页帮助使用者选择安装路径，也说明系统维护者需要交付哪些适配。当前板卡为 **`100ask_t113s3-pro`**，配套系统为 TinaSDK 5.0 v1.2 / OpenWrt，屏幕为 3.52 英寸 240×360 单色 EPD。其他 Linux 系统和板卡按下述流程接入，具体可安装范围以对应 Release 的目标矩阵为准。

EinkOS 将 Linux 系统、桌面应用和用户数据分别管理。桌面采用独立应用发布与自动更新架构；系统提供驱动、基础库、服务管理及可信更新环境。一次应用更新不要求重新安装 Linux。两条升级路径见[应用与系统 OTA 的区别](SYSTEM_OTA.md)。

## 1. 先识别板卡和系统

在目标板终端记录板卡型号、硬件修订、存储型号、屏幕分辨率和当前系统版本。可用以下只读命令辅助检查：

```sh
uname -m
cat /etc/os-release
eink-dashboard --version
```

旧 Tina 镜像可能没有 `/etc/os-release`，此时依据镜像发布记录核对 SDK 和系统身份。`uname -m` 只能辅助确认 CPU 架构，不能证明 libc、浮点 ABI、驱动和应用包兼容。

接入 OTA 的新系统还须提供受系统管理的接口契约，规范建议位置为 `/etc/einkos/system-release.json`。它记录系统版本、板型、运行库和更新器能力；**这不是旧镜像必定存在的文件**。缺少契约时先由系统维护者完成基线接入，不能手工填写一个文件就开始自动更新。

## 2. 按系统选择安装路径

手机阅读下表时，可在表格区域左右滑动查看各列。

| 目标环境 | 首次安装方式 | 日常运行与维护 | 应用更新接入条件 |
| --- | --- | --- | --- |
| 当前 `100ask_t113s3-pro` Tina / OpenWrt | 使用对应 NAND / 屏幕配置的镜像，经 LYNX 烧录 | procd 管理桌面和连接服务；按当前用户指南使用 | 历史镜像先核对更新器能力；当前仓库尚无已交付的应用 OTA 实现 |
| 其他 OpenWrt 板级系统 | 使用该板已适配的镜像和 LYNX 安装流程 | 接入实际网络、蓝牙、显示后端和服务依赖 | 配方、ABI、更新器、受管目录及恢复链路逐板验证；不能直接套 Tina 包 |
| Buildroot 系统 | 将固定版本应用及依赖集成进该板 rootfs，再交付完整镜像 | 按实际配置使用 BusyBox init、SysV 或 systemd；Buildroot 本身不决定服务管理方式 | 提供可持久化应用版本区、数据区、更新服务和健康检查；只读 rootfs 需单独设计可写区域 |
| Yocto 系统 | 用 recipe/layer 固定应用来源，在板级发行版中生成镜像 | 使用该发行版实际选择的 init、网络及日志服务 | recipe 与运行时更新器明确文件所有权，验证签名、升级和恢复；不能只凭有包管理器判断支持 OTA |
| Debian / Ubuntu / Armbian 等板级发行版 | 先安装匹配板卡的系统；维护者提供兼容包或预集成镜像后再安装 EinkOS | 通常使用 systemd；需要专用显示/输入适配和服务权限 | 分别核对 armhf/aarch64、glibc、驱动和服务契约；本仓库尚未提供通用 `.deb` 安装入口 |

后四项是接入指南，尚不是这些发行版已全部适配的承诺。Tina 工具链路径中出现 `buildroot`，也不意味着现有 Tina 应用包适用于任意 Buildroot 系统。

### 当前 Tina / OpenWrt 用户

1. 按[硬件说明](HARDWARE.md)核对板卡、NAND 配置和屏幕。
2. 从匹配 Release 获取镜像与校验资料，备份书籍、设置和阅读记录。
3. 按[LYNX 安装流程](INSTALL.md)烧录，完成[首次启动检查](QUICKSTART.md)。
4. 按[用户指南](USER_GUIDE.md)使用桌面，按[配置与备份](CONFIGURATION.md)维护数据。
5. 更新前检查所装系统是否明确交付了应用更新器；有则按[应用 OTA](APPLICATION_OTA.md)选择渠道，无则等待兼容基线或使用已验证的系统安装路径。

现有版本可以在目标板检查服务日志：

```sh
eink-dashboard --version
ls -l /dev/epd_100ask
logread | grep -i eink
```

### 其他系统的维护者

1. 先完成该板 Linux 的启动、显示驱动、按键和存储验证，再选择匹配工具链与 sysroot 编译应用。
2. 适配显示、输入、网络/蓝牙、时间和服务管理；Tina 的 `/bin/wifi`、`libbtmg.so` 与 procd 不能直接移植成通用依赖。
3. 为目标 init 提供服务定义，规定启动顺序、停止顺序、权限、日志及故障重启。当前仓库只有 OpenWrt 服务脚本，没有通用 systemd unit。
4. 选择一种应用文件所有者：系统包管理器或专用更新器。不要让 apt/opkg 与 OTA 更新器同时覆盖同一套文件。发行版自动更新服务也不得绕过本应用的兼容及回退要求。
5. 按[多板与屏幕接入](BOARD_PORTING.md)交付目标矩阵、安装说明、截图与验收记录，再开放安装包。

`apt upgrade`、OpenWrt 的系统更新命令、手工复制二进制，都不能代替 EinkOS 应用 OTA 的完整事务和回退流程。维护者尚未交付实际包名及命令前，本页不提供可直接执行的安装命令。

## 3. 保持使用体验和数据路径稳定

不同系统可以使用不同驱动和服务管理器，但桌面上的日历、阅读、连接、设置等行为由应用版本决定。新平台须明确哪些功能可用；缺少蓝牙硬件时显示不可用，不伪造成功状态。

现有程序入口为 `/usr/bin/eink-dashboard`、`/usr/bin/eink-connectd`，配置为 `/etc/eink-dashboard.conf`，状态位于 `/etc/eink-os/`。书籍位于 `/mnt/UDISK/books` 或 `/mnt/SDCARD/books`。应用版本目录与这些数据应分开；新系统更改挂载点或布局时须提供显式迁移和恢复说明。

安装后分别检查 Linux 启动、桌面启动、实际屏幕刷新、按键、阅读状态保存及网络功能。编译成功或进程存在不能代替这些检查。

## 4. 从旧系统迁移到可自动更新基线

先发布带可信更新器、系统契约和数据保护方案的新系统基线，验证从旧系统迁移和恢复。用户备份后安装该基线，再走应用 OTA；后续兼容应用不再要求重刷镜像。系统迁移保留原始镜像的预装应用身份，并单独记录设备当前应用版本。

旧镜像是否能够在线迁移，取决于它本身是否具有经过验证的系统升级能力。无法证明安全迁移时使用 LYNX 安装/恢复，不通过应用包临时修改分区、信任根或系统基础库。
